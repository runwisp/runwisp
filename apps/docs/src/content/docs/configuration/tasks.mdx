## Identity & metadata

### `[tasks.<name>]`

**type**: `string` **required**

The text after `tasks.` is the task's name: `[tasks.backup-db]` is a task
called `backup-db`. The name is used in the Web UI, TUI, API, CLI, and log
directory.

- Letters, digits, and `. _ - :`, up to 100 characters.
- Must be unique across `[tasks.*]` and [`[services.*]`](/configuration/services/).
- A name with `.` or `:` must be quoted (`[tasks."db:backup"]`).

```toml
[tasks.backup-db]
run = "pg_dump app | gzip > /backups/app.sql.gz"

[tasks."db:backup"]  # quotes required: not a bare TOML key
run = "..."
```

## Scheduling

### cron

**type**: `string`

When the task runs, as a cron expression. Without it, the task runs only when
started by hand. Accepts 5 fields (`min hour day month weekday`), 6 fields with
a leading seconds field, or an `@` shorthand.

```toml
[tasks.healthcheck]
cron = "*/30 * * * * *" # every 30s, aligned to :00 and :30
run  = "curl -fsS http://localhost:8080/healthz"
```

Possible values:

- `*/5 * * * *`: every 5 minutes
- `0 3 * * *`: every day at 03:00
- `0 9 * * 1-5`: 09:00 Monday to Friday
- `*/30 * * * * *`: every 30 seconds (6-field, leading seconds)
- `@hourly`, `@daily`: shorthand forms
- `@every 1h30m`: fixed interval, ignores wall-clock alignment

[How scheduling works](/concepts/scheduling/) has the full cron grammar, DST
rules, and catch-up details. `runwisp validate` runs the same checks as daemon
startup, so it catches a bad cron expression before you deploy.

### run_on_start

**type**: `boolean` **default**: `false`

Run the task once when the daemon starts, like cron's `@reboot`. This is
separate from [`cron`](#cron) and [`catch_up`](#catch_up).

```toml
[tasks.warm-cache]
run_on_start = true
run          = "/usr/local/bin/warm-cache"
```

### catch_up

**type**: `integer` **default**: `1` **min**: `0` **max**: `10000`

How many runs missed while the daemon was down are run at startup.

- `0`: run none. Good for jobs that run every minute.
- `1`: run only the most recent missed one. Good for a daily sync.
- `N`: run up to the `N` most recent. Good for queue processors.

A value above `1` requires `on_overlap = "queue"`, because the missed runs start
one after another.

```toml
[tasks.hourly-roll]
cron       = "0 * * * *"
catch_up   = 24
on_overlap = "queue"
```

### jitter

**type**: `duration` **max**: `24h`

The longest this task's start may be delayed so that jittered tasks with the
same start time (like 03:00) run one after another instead of all at once. It
is a maximum, not a fixed delay: with nothing else jittered running, the task
starts on time.

- Doesn't apply to manual runs, retries, or catch-up runs.
- Needs [`cron`](#cron).

```toml
[tasks.nightly-report]
cron   = "0 3 * * *"
jitter = "30m"  # start may slip up to 30m while other jittered runs are busy
```

Set it in [`[defaults]`](/configuration/defaults/) to apply it to every cron
task.

### timezone

**type**: `string` **default**: [`[daemon] timezone`](/configuration/daemon/#timezone), then the host zone

The IANA zone this task's [`cron`](#cron) is read in. Follows daylight saving
time.

```toml
[tasks.eu-market-open]
cron     = "0 9 * * 1-5"
timezone = "Europe/Bratislava"
```

## Concurrency

### on_overlap

**type**: `enum` **default**: `"queue"`

What happens when the task is triggered while already at
[`max_concurrent`](#max_concurrent) (default `1`).

```toml
[tasks.queue-drain]
cron       = "*/10 * * * *"
on_overlap = "skip"
```

Possible values:

- `queue`: the new run waits and starts when a slot frees up (queue size bounded by [`max_queued`](#max_queued))
- `skip`: the new run is dropped and recorded as skipped
- `kill`: the running run is stopped so the new one takes over

### max_concurrent

**type**: `integer` **default**: `1` **min**: `1` **max**: `1024`

How many runs of this task may be active at once. At the limit,
[`on_overlap`](#on_overlap) decides what happens to the next trigger.

```toml
[tasks.thumbnailer]
max_concurrent = 4
```

### max_queued

**type**: `integer` **default**: `100` **min**: `0` **max**: `10000`

With `on_overlap = "queue"`, the cap on runs waiting in line. Past the cap,
further triggers record `end_reason = "queue_full"`.

```toml
[tasks.ingest]
on_overlap = "queue"
max_queued = 500
```

## Retries & timeout

### timeout

**type**: `duration` **default**: none (no limit)

The longest one attempt may run. A longer run is stopped (with
[`stop_signal`](#stop_signal), then [`graceful_stop`](#graceful_stop)) and
recorded as `timeout`. `"0s"` turns off a `[defaults]` timeout.

```toml
[tasks.queue-drain]
cron    = "*/10 * * * *"
timeout = "9m"
```

### retry_attempts

**type**: `integer` **default**: `0` **min**: `0` **max**: `100`

Extra attempts after the first one fails. A retry happens only when the reason
is `failed`, `timeout`, `crashed`, `log_overflow`, or `start_failed`, **and**
[`failures`](#failures) counts the run as a failure. A manual stop or a kill ends
the retries.

```toml
[tasks.flaky-fetch]
retry_attempts = 3
retry_delay    = "2s"
```

### retry_delay

**type**: `duration` **default**: `5s`

The wait before the first retry. Used only when
[`retry_attempts`](#retry_attempts) is above `0`;
[`retry_backoff`](#retry_backoff) decides how it grows.

```toml
[tasks.flaky-fetch]
retry_attempts = 3
retry_delay    = "5s"
```

### retry_backoff

**type**: `enum` **default**: `"constant"`

How [`retry_delay`](#retry_delay) grows across attempts.

```toml
[tasks.flaky-fetch]
retry_attempts = 4
retry_delay    = "2s"
retry_backoff  = "exponential"  # 2s, 4s, 8s, 16s
```

Possible values:

- `constant`: the same [`retry_delay`](#retry_delay) before every attempt (2s, 2s, 2s, 2s)
- `linear`: [`retry_delay`](#retry_delay) times the attempt number (2s, 4s, 6s, 8s)
- `exponential`: double each time (2s, 4s, 8s, 16s)

The computed delay is capped at 5m, regardless of `retry_backoff`.

### Fail-fast

RunWisp starts [`run`](#run) as `<shell> -e -c <script>`. A multi-line script
stops at the first command that fails, and that exit code becomes the run's
exit code. You don't need `set -e`.

- `-u` and `-o pipefail` are not set. For `pipefail`, set [`shell`](#shell) to
  `/bin/bash` and add `set -o pipefail` to the script.
- To turn fail-fast off for a task, start [`run`](#run) with `set +e`.
- For one command that may exit non-zero, add `|| true`.

## What counts as a failure

:::note[The failure model]
Every run ends with a reason. [`failures`](#failures) decides which reasons and
exit codes turn a run red and fire [`notify`](#notify).

- A token is a reason name, an exit code, an inclusive range (`"42"`,
  `"1-23"`), or an output pattern (`"output:(?i)error"`). Codes are 1 to 255.
- Exit `0` is a success unless an output pattern matched a line of stdout or
  stderr. Then the run ends as `failed`, and its log notes which pattern matched.
- With `"failed"` in the list, every non-zero exit is a failure. Without it,
  only the listed codes fail; other non-zero exits are recorded and shown, but
  are not red and don't notify.
- A bare list replaces the inherited set. Prefix every token with `+` or `-` to
  change the inherited set instead. You can't mix the two styles in one list.

It also limits [`retry_attempts`](#retry_attempts) and services'
`restart = "on_failure"`: only runs counted as failures are run again. Adding
`stopped` or `missed` never causes a retry.
:::

### failures

**type**: `string[]` **default**: `["failed", "timeout", "crashed", "log_overflow", "start_failed", "missed"]`

Which run outcomes count as a failure.

```toml
[tasks.web]
failures = ["-missed"]              # stop paging on a missed tick

[tasks.rsync]
failures = ["timeout", "23", "24"]  # only these exits fail

[tasks.report]
failures = ["+output:(?i)error"]    # also fail when a line says "error"
```

Possible values:

- `failed`: the command exited non-zero or was killed by a signal
- `timeout`: stopped for running longer than [`timeout`](#timeout)
- `crashed`: still running when the daemon itself was killed (recorded at the next start)
- `log_overflow`: hit [`log_max_size`](#log_max_size) under `log_on_full = "kill"`
- `start_failed`: a service gave up after too many fast restarts (see [`restart_attempts`](/configuration/services/#restart_attempts))
- `missed`: a scheduled firing was skipped while the daemon was down
- `stopped`: an operator stopped the run
- `daemon_stopped`: still running when the daemon shut down
- `skipped`: dropped because a run was already going under [`on_overlap = "skip"`](#on_overlap)
- `queue_full`: dropped because the queue already held [`max_queued`](#max_queued) runs
- `dst_skipped`: the second of two identical firings when the clock falls back for DST
- `output:<regex>`: a stdout or stderr line matched the [RE2](https://github.com/google/re2/wiki/Syntax) pattern, even if the command exited 0. Use `(?i)` to ignore case.

## Parameters

For an introduction, see [Parameters](/concepts/parameters/).

### params

**type**: `table` (array of `[[tasks.<name>.params]]` entries)

The inputs a task takes. Each one becomes a field on the Run form in the Web
UI, TUI, and REST API. Each entry has exactly one kind keyword (`env`, `arg`,
`option`, or `flag`) that decides how the value reaches your command.

- Values are passed as real arguments or env vars, never pasted into the shell
  string, so input like `; rm -rf /` is harmless.
- Scheduled runs (cron, catch-up, retries) use the declared defaults.

```toml
[tasks.backup]
run = "/usr/local/bin/backup.sh"
params = [
  { env = "PROJECT_ID", required = true },
  { arg = "source", required = true },
  { arg = "dest", default = "/backups" },
  { option = "--region", choices = ["us", "eu"] },
  { flag = "--force" },
]
```

Kind keyword (exactly one per entry):

- `env`: pass the value as an environment variable with this name. The name
  can't also be an [`env`](#env) or [`secrets`](#secrets) key on the same task.
- `arg`: append the value as a positional argument, in declaration order.
- `option`: render as `--name value`. A name ending in `=` glues them
  (`--date=2026-01-01`).
- `flag`: a boolean whose token is appended when on, omitted when off. Takes no
  `choices` or `type`.

Attributes:

- `default`: the value scheduled runs use and the manual form starts with
  (`true`/`false` for a flag).
- `required`: the manual form won't submit without a value (`env`, `arg`,
  `option`). A required parameter on a scheduled task must also set `default`.
- `type`: `string` (default) or `number`. A value that isn't a number is
  rejected before the run starts.
- `choices`: a fixed list, shown as a dropdown. Other values are rejected.
- `allow_custom`: with `choices`, also allow a value not in the list. Rejected
  without `choices`.
- `description`: help text shown under the field.

:::note[Empty field vs. empty string]
On a manual run:

- A filled field (the default or your value) is passed.
- A cleared field is not passed at all: no option, arg, or env var. It does
  not fall back to the default. A `required` field can't be cleared.
- To pass an empty string (`--note ''`), use the toggle under the field (in the
  TUI, <kbd>ctrl+t</kbd>).

A flag that is off is not passed. A retry uses exactly the values of the
original run.
:::

## Compose-backed tasks

A task can run a compose service instead of a shell command:

```toml
[tasks.nightly-backup]
cron            = "0 3 * * *"
compose_file    = "./docker-compose.yml"
compose_service = "backup"
```

### compose_mode

<ComposeMode />

To import every service in a compose file, see
[`[compose.*]`](/configuration/compose/).

:::note[Parameters on a compose task]
[Parameters](#params) work here. In new-container mode (no [`run`](#run)),
`arg`, `option`, and `flag` values are passed like `docker compose run <svc> …`
arguments: they replace the service's `command:` and go to the image's
`ENTRYPOINT`.

```toml
[tasks.nightly-backup]
cron            = "0 3 * * *"
compose_file    = "./docker-compose.yml"
compose_service = "backup"
params          = [{ arg = "since", default = "yesterday" }]
```

:::

## What's rejected on tasks

The config fails to load with any of these:

- Service-only keys: [`restart`](/configuration/services/#restart),
  [`restart_attempts`](/configuration/services/#restart_attempts),
  [`restart_delay`](/configuration/services/#restart_delay),
  [`restart_backoff`](/configuration/services/#restart_backoff),
  [`healthy_after`](/configuration/services/#healthy_after),
  [`instances`](/configuration/services/#instances),
  [`priority`](/configuration/services/#priority),
  [`autostart`](/configuration/services/#autostart),
  [`depends_on`](/configuration/services/#depends_on). A task uses
  [`retry_attempts`](#retry_attempts) instead of restarts.
- A name already used by a `[services.*]` entry.
- An empty or missing [`run`](#run) (unless [`compose_file`](#compose_file) is set).
