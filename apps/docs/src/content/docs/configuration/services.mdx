A service is a long-running process. RunWisp restarts it when it exits or
crashes, until you stop it. This page lists every key a `[services.<name>]`
block accepts. Unset keys fall back to [`[defaults]`](/configuration/defaults/),
then a built-in default.

## Identity & metadata

### `[services.<name>]`

**type**: `string` **required**

The text after `services.` is the service's name: `[services.api-worker]` is a
service called `api-worker`. The name is used in the CLI, API, Web UI, and log
directory.

- Letters, digits, and `. _ - :`, up to 100 characters.
- Must be unique across `[services.*]` and [`[tasks.*]`](/configuration/tasks/).
- Quote names that aren't a bare TOML key (`[services."api:v2"]`).

```toml
[services.api-worker]
run = "/usr/local/bin/worker"
```

## Instances

### instances

**type**: `integer` **default**: `1` **min**: `1` **max**: `64`

How many copies of the process run at once.

- Each instance is its own run with an `instance_index` (`0`, `1`, `2`, …). The
  Web UI and TUI show them as `name#1`, `name#2`; a single instance is just
  `name`.
- All instances share the config and the log view.
- When one instance exits, only that one is restarted.

```toml
[services.api-worker]
instances = 3
run       = "/usr/local/bin/worker"
```

## Restart behaviour

For a command that should run once and exit, use a
[task](/concepts/tasks-vs-services/).

### restart

**type**: `enum` **default**: `"always"`

When an instance is started again after it exits.

```toml
[services.worker]
restart = "on_failure"
```

Possible values:

- `always`: restart after any exit
- `on_failure`: restart only when [`failures`](#failures) counts the exit as a
  failure (and the reason is `failed`, `timeout`, `crashed`, `log_overflow`, or
  `start_failed`)
- `never`: don't restart; one exit is final

A manual **Restart** always starts the instance again, whatever this is set to.

### restart_delay

**type**: `duration` **default**: `1s`

The base wait before an automatic restart. [`restart_backoff`](#restart_backoff)
decides how it grows. `0` is allowed and means no wait. A manual **Restart**
never waits.

```toml
[services.flaky]
restart_delay = "2s"
```

### healthy_after

**type**: `duration` **default**: `60s`

How long an instance must stay up to count as healthy. Reaching it resets the
restart backoff and the failed-start count used by
[`restart_attempts`](#restart_attempts).

```toml
[services.api-worker]
healthy_after = "2m"
```

### restart_attempts

**type**: `integer` **default**: `3` **min**: `0` **max**: `100`

How many failed starts in a row an instance may have before it goes
[FATAL](#when-a-service-cant-start-fatal) and stops restarting. `0` gives up
after the first failed start.

```toml
[services.flaky]
restart_attempts = 2
```

### restart_backoff

**type**: `enum` **default**: `"exponential"`

How [`restart_delay`](#restart_delay) grows after each restart. The delay has an
upper limit.

```toml
[services.flaky]
restart_backoff = "exponential"
```

Possible values: `constant`, `linear`, `exponential` (the same curves as
[`retry_backoff`](/configuration/tasks/#retry_backoff)).

### When a service can't start: FATAL

A **failed start** is a failure exit before the instance reached
[`healthy_after`](#healthy_after). A clean exit (success code) never counts.

- After more than [`restart_attempts`](#restart_attempts) failed starts in a
  row, the instance goes **FATAL**: it stops restarting, a `start_failed` run is
  recorded, and a `service.fatal` notification goes to the in-app bell and your
  [notifiers](/notifications/).
- FATAL is kept in memory only. A daemon restart, or **Restart** in the UI or
  API, resets the count and tries again.
- The `start_failed` runs stay in history.

```toml
[services.flaky]
run              = "exit 1"   # can never come up
healthy_after    = "5s"       # must stay up 5s to count as healthy
restart_attempts = 2          # give up after 2 failed starts in a row
```

## Startup

### autostart

**type**: `boolean` **default**: `true`

Whether the service starts when the daemon starts. With `false`, it stays
stopped until you start it from the UI or API.

This is read from `runwisp.toml` at every boot, not saved: a manually started
`autostart = false` service is stopped again after a daemon restart, and a
manually stopped `autostart = true` service starts again.

```toml
[services.migration-runner]
autostart = false
```

### priority

**type**: `integer` **default**: `0`

Start order at boot. Lower starts first; equal values start in name order. It
doesn't wait for a service to be ready. For that, use
[`depends_on`](#depends_on).

```toml
[services.db]
priority = 0

[services.api]
priority = 10
```

## Boot order with `depends_on`

### depends_on

**type**: `string[]` **default**: none

Services that must be healthy (at least one instance up for its
[`healthy_after`](#healthy_after)) before this one starts at boot.

```toml
[services.db]
run           = "postgres -D /var/lib/pg"
healthy_after = "3s"

[services.api]
run        = "./api-server"
depends_on = ["db"]  # start after db is healthy
```

- If a dependency never becomes healthy, the service waits a limited time, then
  starts anyway and logs a warning.
- It applies only to the automatic start at boot. Manual start and restart
  don't wait.
- At shutdown, dependent services stop first.
- Names must be existing services (not tasks). Cycles are rejected at load.
- There are no restart cascades or data passing between services. See
  [Tasks vs Services](/concepts/tasks-vs-services/).

## Concurrency

Services have no [`on_overlap`](/configuration/tasks/#on_overlap),
[`max_concurrent`](/configuration/tasks/#max_concurrent), or
[`max_queued`](/configuration/tasks/#max_queued). The number of running copies
is set by [`instances`](#instances).

## Timeout & failures

### timeout

**type**: `duration` **default**: none (no limit)

The longest an instance may run. After that it is stopped and recorded as
`timeout`, then [`restart`](#restart) decides what happens next.

```toml
[services.report-server]
timeout = "24h"
```

### failures

**type**: `string[]` **default**: `["failed", "timeout", "crashed", "log_overflow", "start_failed", "missed"]`

Which outcomes count as a failure: they turn the run red, fire [`notify`](#notify),
and (with `restart = "on_failure"`) cause a restart. Same syntax as on tasks; see
[What counts as a failure](/configuration/tasks/#what-counts-as-a-failure).

```toml
[services.web]
failures = ["-missed"]
```

## Graceful shutdown

### graceful_stop

<GracefulStop />

It applies to each instance, on manual stop, **Restart**, and daemon shutdown.
At daemon shutdown, [`shutdown_timeout`](/configuration/daemon/#shutdown_timeout)
still limits it.

To stop cleanly, trap the stop signal in [`run`](#run) and exit. An instance
that exits after `SIGTERM` is recorded as `stopped`:

```bash
trap 'echo "shutting down"; exit 0' TERM INT
while true; do
  # do work
done
```

## Compose-backed services

A service can run a service from an existing `docker-compose.yml` instead of a
shell command:

```toml
[services.api]
compose_file    = "./docker-compose.yml"
compose_service = "api"
notify          = ["slack-prod"]
```

To import every service in a compose file, see

## What's rejected on services

- [`cron`](/configuration/tasks/#cron), [`catch_up`](/configuration/tasks/#catch_up):
  services don't run on a schedule.
- [`params`](/configuration/tasks/#params): services don't take parameters.
- [`retry_attempts`](/configuration/tasks/#retry_attempts),
  [`retry_delay`](/configuration/tasks/#retry_delay),
  [`retry_backoff`](/configuration/tasks/#retry_backoff): use
  [`restart_delay`](#restart_delay) and [`restart_backoff`](#restart_backoff).
- [`on_overlap`](/configuration/tasks/#on_overlap),
  [`max_concurrent`](/configuration/tasks/#max_concurrent),
  [`max_queued`](/configuration/tasks/#max_queued): use [`instances`](#instances).
- A name already used by a `[tasks.*]` entry.
- An empty or missing [`run`](#run) (unless [`compose_file`](#compose_file) is set).
- [`instances`](#instances) outside `1` to `64`.
