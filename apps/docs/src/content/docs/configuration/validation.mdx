RunWisp's loader is **strict**. A misshapen `runwisp.toml` fails the
boot before the daemon opens its port — better than a silent wrong
default at 03:00 in the morning. This page is the catalogue of every
shape the loader refuses, grouped by where the failure surfaces.

`runwisp validate --config <path>` runs the same checks without
starting the daemon. (The path is consumed via the persistent
`--config` flag — there is no positional path argument.) Use it as a
pre-flight before restarting in production; it's also what the test
suite exercises.

## Document-level rules

These checks fire on the file as a whole, before any per-task work.

| Rejected shape                                      | Why                                                                                                                                                                |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Unknown TOML key anywhere                           | The decoder runs in strict mode (`DisallowUnknownFields`). A typo like `keep_run = 5` or `tasks.foo.descripton` fails the parse.                                   |
| Empty / whitespace-only task name                   | `[tasks.""]` and `[tasks." "]` are rejected — the table key is the task identity used in CLI, API, log paths.                                                      |
| Empty / whitespace-only service name                | Same rule for `[services.*]`.                                                                                                                                      |
| Same name in `[tasks.*]` and `[services.*]`         | The two tables share one namespace — the CLI, API, and log directory layout key off the name. Pick one or rename.                                                  |
| Duplicate task name (post-decode)                   | Defence-in-depth: if a future change introduces a path that bypasses the TOML map, validation still rejects two tasks with the same name.                          |
| `graceful_stop` exceeds `[daemon] shutdown_timeout` | Not rejected — but the daemon emits a boot-time warning naming the task, since whole-daemon shutdown will SIGKILL the survivor before its per-task window expires. |

## Per-task / per-service rules

Both `[tasks.*]` and `[services.*]` are validated row by row.

### Required fields

| Rejected shape         | Why                                                                                                         |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| Missing or empty `run` | A task with no command has nothing to do. `run = ""` and `run = "   "` (whitespace-only) are both rejected. |
| Missing table key      | TOML cannot express this — but `[tasks.""]` and `[services.""]` are caught explicitly.                      |

### Wrong-table errors

These are placed where a friendly redirect helps more than a generic "unknown key".

| Rejected shape                                                             | Why                                                                                                                |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `restart = "always"` on `[tasks.*]`                                        | Always-on processes belong in `[services.*]`. The error names the table to use.                                    |
| `instances = N` on `[tasks.*]`                                             | `instances` is a service-only knob (replica count). Tasks already have `max_concurrent` for in-flight concurrency. |
| `cron = "…"` on `[services.*]`                                             | Services are not cron-driven. Rejected as an unknown key by the strict decoder.                                    |
| `catch_up = "…"` on `[services.*]`                                         | Same — services don't have a missed-firing concept.                                                                |
| `max_concurrent = N` on `[services.*]` / `queue_max = N` on `[services.*]` | Services don't queue overlap; replica count is `instances`.                                                        |
| `parallelism = N` (anywhere)                                               | Renamed to `max_concurrent` on tasks; removed entirely on services. The error suggests the new name.               |

### Enum membership

Every enum field rejects values outside its allowed set. The empty
string is treated as "use the default" for fields that have one.

| Field             | Allowed values                      |
| ----------------- | ----------------------------------- |
| `on_overlap`      | `queue`, `skip`, `terminate`        |
| `restart` (tasks) | `never`, `on_failure` (and empty)   |
| `retry_backoff`   | `constant`, `linear`, `exponential` |
| `restart_backoff` | `constant`, `linear`, `exponential` |
| `log_on_full`     | `drop_new`, `drop_old`, `kill_task` |
| `catch_up`        | `latest`, `all`, `skip`             |

### Numeric ranges and hard caps

Every numeric field is a literal integer (or duration / byte size).
There are **no** magic-int sentinels and **no** keyword forms — `0` is
zero, negatives are config errors, and "no cap" is spelled by omitting
the field. Each field has an internal hard cap; values above the cap
are rejected with a hint.

| Field               | Rule                                                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `max_concurrent`    | Tasks: `>= 1`; hard cap **1024**. Zero would mean "the task can never run", which is what omitting it (or removing the task) is for. |
| `queue_max`         | Tasks with `on_overlap = "queue"`: `>= 1`; hard cap **10000**. Zero is rejected — use `on_overlap = "skip"` for "never queue".       |
| `retry_attempts`    | `>= 0`; hard cap **100**.                                                                                                            |
| `max_catch_up_runs` | `>= 1`; hard cap **10000**.                                                                                                          |
| `keep_runs`         | `>= 1`; hard cap **1 000 000**. Bare `0` and negatives are rejected. Omit the field to inherit / disable the cap.                    |
| `instances`         | Services only: `>= 1` and `<= 64`.                                                                                                   |

### Retention and log size

| Field          | Accepted                                               | Rejected                                                                                                  |
| -------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| `keep_runs`    | Positive integer (`50`); or omitted (no cap).          | `0`, negative integers, any string, the words `"unlimited"` / `"inherit"`.                                |
| `keep_for`     | Positive duration (`"30d"`, `"2w"`, `"36h"`); omitted. | Empty `""`, `"0"` / `"0s"`, negative durations, malformed strings, the words `"unlimited"` / `"inherit"`. |
| `log_max_size` | Positive byte size (`"100mb"`, `"1.5gb"`); omitted.    | `0`, `"0"`, `"0mb"`, negative sizes, malformed strings, the words `"unlimited"` / `"inherit"`.            |

The pre-0.5 `"unlimited"` and `"inherit"` keywords were dropped — they
were ambiguous (was inherit pulling from defaults, or just "use the
built-in"?) and made misread zeros silently mean unlimited. To opt out
of a cap, simply omit the field at every scope. The error message for
each rejected keyword suggests the new shape.

### Durations

`timeout`, `retry_delay`, `restart_delay`, `graceful_stop`, and
`backoff_reset_after` use Go's `time.ParseDuration` syntax (`"1h30m"`,
`"500ms"`). `keep_for` and `notify.history_keep_for` add `d` and `w`
suffixes. Empty string falls through to defaults (or "no limit" for
`timeout`); malformed strings fail the load.

### Timezone

`[scheduler] timezone` (and any per-task `timezone`) must parse via
Go's `time.LoadLocation`. The error names the bad value:

```
invalid timezone for task my-task: "Pacific/Atlantis" is not a valid
IANA timezone (e.g. "UTC", "Europe/Bratislava"): unknown time zone …
```

`[scheduler] timezone` is **not required**: if it's omitted (and no
per-task `timezone` is set on the cron task either), the daemon falls
back to the host's system timezone. The resolved zone is shown in the
TUI startup banner and the Web UI header so the operator can see
which one is in effect. `runwisp init` writes the detected system
zone for you so a fresh install starts with explicit, visible config.

## Cron expressions

`cron` strings are parsed by [robfig/cron's standard parser](https://pkg.go.dev/github.com/robfig/cron/v3) and accept the
five-field form (`* * * * *`) as well as the descriptors `@hourly`,
`@daily`, `@weekly`, `@monthly`, `@yearly`, and the interval form
`@every 1h30m`. A malformed expression does **not** fail the config
load — `runwisp validate` accepts it. The cron parser only runs at
scheduler startup, where it emits a warning to stderr and leaves the
task unscheduled (manual triggers still work). To catch a typo before
production, boot the daemon against the new file (or `runwisp daemon
--config <path>` in a scratch data dir) and watch the startup log;
`runwisp validate` will not flag it.

## Notifications

| Rejected shape                                                                   | Why                                                                                                    |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Notifier id containing `:`                                                       | The colon is reserved as the inline-target separator (`"slack-ops:#deploys"`). Rename the notifier.    |
| Notifier `id` collision                                                          | Two `[[notifier]]` blocks with the same `id` are rejected — the id is the routing key.                 |
| `[[notifier]] type` outside `slack` / `telegram`                                 | Unknown providers fail at load.                                                                        |
| Multiple secret sources on one notifier (e.g. `webhook_url` + `webhook_url_env`) | Exactly one source per secret. Pick env var, file, or inline literal.                                  |
| Empty `[[notification_route]] notify`                                            | A route with no target is unreachable; treat as a config error.                                        |
| Token referencing an unknown notifier id                                         | `notify_on_failure = ["nope"]` fails — `nope` must match a `[[notifier]]` id (or the literal `inapp`). |

See [Notifications model](/notifications/model/) for the runtime
behaviour these checks defend.

## What is **not** validated at load

- **Cron expressions** — see the note above; the scheduler logs warnings
  for unparseable specs but the daemon still boots.
- **Reachability of secret files / env vars** — the loader records the
  source; the secret resolver in the notification subsystem fetches at
  send time. A missing env var triggers a runtime delivery failure, not
  a load failure.
- **Network endpoints** — Slack webhook URLs and Telegram bot tokens
  are not pinged at boot; that would block startup behind an outbound
  request, which violates the "no required network" invariant.
- **Disk free-space** at boot — `[storage] min_free_space` is enforced
  during runs, not at parse time.
