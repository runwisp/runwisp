The `[notify]` table is where the daemon-wide knobs live: which channels
catch every failure, how long an outbound delivery keeps retrying, how
much bell history to hang onto, how hard to coalesce. Every key is
optional, and the defaults are tuned for a single-machine setup.

This isn't the page for declaring channels or routing rules, though —
that's [`[notifiers.<id>]`](/notifications/model/#notifiersid--declaring-a-channel)
and [`[[route]]`](/notifications/routes/).

## Keys

```toml
[notify]
global_notifiers  = ["inapp"]   # default — bell on
# retry_budget = "30s"       # unset — uses the built-in 5-min retry budget
keep_notifications      = 1024        # default
keep_for  = "90d"       # default
coalesce_window   = "1h"        # default
coalesce_every   = 10          # default
```

| Key                  | Default     | What it does                                                                                                                                                                                                  |
| -------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `global_notifiers`   | `["inapp"]` | Channels added to every per-task notify list (deduplicated), and catch-all for tasks without one. Set `[]` to silence the bell.                                                                               |
| `retry_budget`       | _(unset)_   | Caps the total retry budget for one outbound delivery. Unset = 5 minutes.                                                                                                                                     |
| `keep_notifications` | `1024`      | Cap on bell rows kept in SQLite. Older rows are pruned in one pass.                                                                                                                                           |
| `keep_for`           | `90d`       | Maximum age of bell rows. Accepts `d` and `w` units.                                                                                                                                                          |
| `coalesce_window`    | `1h`        | Window during which repeats with the same kind for the same task update one row instead of writing a new one. Set `"0s"` to send one outbound message per event (the bell still coalesces).                   |
| `coalesce_every`     | `10`        | Recent timestamps kept on each coalesced bell row, and how many suppressed events it takes before an outbound delivery (Slack, Telegram, etc.) is force-forwarded instead of waiting for the window to close. |

Set both `keep_notifications` and `keep_for` and they both apply at
once — whichever trims harder is the one that bites.

## The bell — `global_notifiers`

```toml
[notify]
global_notifiers = []                # silence the bell entirely
# global_notifiers = ["slack-ops"]   # or: every failure goes to that channel
```

`global_notifiers = []` switches off the bell in both the Web UI and the
TUI footer, and it also stops `"inapp"` from being slipped into your
per-task fields. With it empty, `notify = ["slack-ops"]` goes
to `slack-ops` and nowhere else.

Reach for the empty form when the daemon runs unattended — a build
agent, a CI shard — and nobody's ever looking at the Web UI. Reach for a
non-empty list when you want every failure funneled to one channel
without sprinkling per-task fields all over the file.

## Retry budget — `retry_budget`

When an outbound delivery hits a transient failure, it retries with
exponential backoff. `retry_budget` is the cap on how much
wall-clock time that whole retry loop is allowed to burn.

Leave it unset and the budget is **5 minutes** — a delivery can keep
trying for that long. Set `retry_budget = "30s"` and you cut it to
half a minute, so a hard outage shows up in the bell that much sooner.

The per-attempt HTTP timeout is a separate thing entirely. Set
`retry_budget` shorter than a single attempt and you've effectively
asked for one try and no retries.

## Bell history

Bell rows live in SQLite, kept separate from run rows. Two knobs prune
them:

- `keep_notifications` — keep at most N rows; older ones are pruned in one
  pass.
- `keep_for` — delete rows older than this duration.

Both run at once, and the stricter one wins. A background sweeper takes
care of it — there's nothing for you to trigger.

## Coalescing

RunWisp folds together repeat events of the same kind for the same task,
so you don't get paged twice for the same thing. A task failing every
minute leaves you one bell row that ticks upward, not 60 separate ones.

- `coalesce_window` — within this window, repeats update the same row:
  `count` climbs and the latest timestamp is recorded.
- `coalesce_every` — how many recent timestamps to keep on the row. The
  UI uses these to draw a sparkline.

`coalesce_every` does double duty: it's also how outbound channels decide
when to break their silence. Slack, Telegram, and the rest queue up
suppressed events during the coalescing window instead of paging you for
each one, but they won't queue forever. Once `coalesce_every` of them have
piled up, the next one goes out anyway as a "check-in" with a count
attached. Lower the value to trim bell history and outbound pages get more
frequent too; raise it and both quiet down. The
[Coalescing section of the model page](/notifications/model/#coalescing)
has the full timeline and the check-in/summary cadence.

Set `coalesce_window = "0s"` to send one outbound message per event. The
bell keeps coalescing on its built-in window regardless — it always wants
one row per kind. To keep outbound grouping but make it tighter, set a
short window like `"1s"`.

## Worked examples

A small server with one outbound channel that wants delivery failures to
surface quickly:

```toml
[notify]
global_notifiers  = ["inapp"]   # keep the bell
retry_budget   = "30s"       # cap retry budget at 30s
keep_notifications      = 2000
keep_for  = "60d"
coalesce_window   = "30m"
coalesce_every   = 20
```

A headless build agent that sends everything off-host:

```toml
[notify]
global_notifiers  = []          # nobody reads the bell
```
