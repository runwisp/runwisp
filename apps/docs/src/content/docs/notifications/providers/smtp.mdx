The SMTP notifier sends one email per event through any SMTP server. Each email
has an HTML part and a plain-text part, so it reads well in Gmail and in `mutt`.
If the machine already sends mail with a local MTA, the
[sendmail notifier](/notifications/providers/sendmail/) needs less setup.

```toml
[notifiers.email-ops]
type     = "smtp"
host     = "smtp.example.com"
port     = 587
from     = "RunWisp <runwisp@example.com>"
to       = ["alerts@example.com"]
username = "apikey"
password = "${SMTP_PASSWORD}"
```

## Fields

| Key               | Required | What it does                                                                                                     |
| ----------------- | -------- | ---------------------------------------------------------------------------------------------------------------- |
| `host`            | yes      | The SMTP server, like `smtp.gmail.com`.                                                                          |
| `port`            | no       | Default `25`. Usually `587` (STARTTLS) or `465` (TLS from the start).                                            |
| `tls_mode`        | no       | `starttls`, `implicit`, or `off`. Default `implicit` on port 465, `starttls` otherwise. `starttls` requires TLS. |
| `tls_skip_verify` | no       | Don't check the server's TLS certificate. Don't use it in production.                                            |
| `username`        | no       | SMTP login. Set together with `password`, or leave both out for a server without login.                          |
| `password`        | no       | SMTP password. Keep it out of the file; see [Storing the secret](/notifications/#storing-the-secret).            |
| `from`            | yes      | The `From:` address: `"name@example.com"` or `"Name <name@example.com>"`.                                        |
| `reply_to`        | no       | A `Reply-To:` address.                                                                                           |
| `to`              | yes      | List of recipients, at least one.                                                                                |
| `cc`              | no       | List of `Cc:` recipients.                                                                                        |
| `bcc`             | no       | List of `Bcc:` recipients.                                                                                       |
| `template_path`   | no       | A Go template file that replaces the built-in HTML message.                                                      |

To send one task's mail to another address through the same server, use
`"email-ops:db-team@example.com"` in `notify`. It replaces the `to`, `cc`, and
`bcc` lists for that task. See
[One channel, several destinations](/notifications/#one-channel-several-destinations).

## Server settings

<Tabs syncKey="smtp-provider">
    <TabItem label="Gmail">
        Gmail needs an [app password](https://myaccount.google.com/apppasswords);
        it rejects your normal password over SMTP.

        ```toml
        [notifiers.email-ops]
        type     = "smtp"
        host     = "smtp.gmail.com"
        port     = 587
        from     = "Your Name <you@gmail.com>"
        to       = ["alerts@example.com"]
        username = "you@gmail.com"
        password = "${GMAIL_APP_PASSWORD}"
        ```
    </TabItem>
    <TabItem label="SendGrid">
        The username is always `apikey`; the password is your API key.

        ```toml
        [notifiers.email-ops]
        type     = "smtp"
        host     = "smtp.sendgrid.net"
        port     = 587
        from     = "RunWisp <alerts@yourdomain.com>"
        to       = ["ops@yourdomain.com"]
        username = "apikey"
        password = "${SENDGRID_API_KEY}"
        ```
    </TabItem>
    <TabItem label="Amazon SES">
        Create SMTP credentials in the SES console under **SMTP settings**. Your IAM
        password doesn't work here.

        ```toml
        [notifiers.email-ops]
        type     = "smtp"
        host     = "email-smtp.eu-west-1.amazonaws.com"
        port     = 587
        from     = "RunWisp <alerts@yourdomain.com>"
        to       = ["ops@yourdomain.com"]
        username = "AKIA..."
        password = "${SES_SMTP_PASSWORD}"
        ```
    </TabItem>
    <TabItem label="Mailgun / Postmark">
        Use your region's host and the credentials they give you.

        ```toml
        # Mailgun
        [notifiers.email-ops]
        type     = "smtp"
        host     = "smtp.eu.mailgun.org"
        port     = 587
        from     = "RunWisp <alerts@yourdomain.com>"
        to       = ["ops@yourdomain.com"]
        username = "postmaster@yourdomain.com"
        password = "${MAILGUN_PASSWORD}"
        ```

        ```toml
        # Postmark
        [notifiers.email-ops]
        type     = "smtp"
        host     = "smtp.postmarkapp.com"
        port     = 587
        from     = "RunWisp <alerts@yourdomain.com>"
        to       = ["ops@yourdomain.com"]
        username = "<server-token>"
        password = "${POSTMARK_TOKEN}"
        ```
    </TabItem>
    <TabItem label="Local Postfix">
        A server on the same machine, without login or TLS. `tls_mode = "off"` only
        works without `username` and `password`.

        ```toml
        [notifiers.email-local]
        type     = "smtp"
        host     = "127.0.0.1"
        port     = 25
        tls_mode = "off"
        from     = "runwisp@myhost"
        to       = ["ops@example.com"]
        ```
    </TabItem>

</Tabs>

## When mail doesn't arrive

If the bell shows a `notify.delivery_failed` warning, it includes the SMTP
error. Common causes:

- The port doesn't match `tls_mode`: port `587` needs `starttls`, port `465`
  needs `implicit`.
- An expired or wrong app password.
- The server rejects a recipient (`550 No such user`).

If nothing failed, check the spam folder. The first mail from a new sender often
lands there.

## What a message looks like

> **❌ backup-postgres failed**
>
> Exited with code 1 after 0.3s.
> Scheduled run · 14 May, 17:11.
>
> ```
> Error: connection refused
> dial tcp 127.0.0.1:5432: connect:
> connection refused
> ```
>
> **[View full run]**
>
> _from runwisp · bright-falcon_

- The output block appears for failures and timeouts, up to three lines or 300
  bytes.
- The **View full run** link appears only when
  [`external_url`](/configuration/daemon/#external_url) is set.
- The footer names the daemon that sent it.
- The plain-text part is made from the HTML, so text-only mail readers see the
  same content.

## Changing the message

Point `template_path` at your own Go template. Start from the built-in
[`smtp.tmpl.html`](https://github.com/runwisp/runwisp/blob/main/apps/runwisp/internal/notify/render/defaults/smtp.tmpl.html).
It gets the whole event, the same helpers as the
[Slack template](/notifications/providers/slack/#changing-the-message), and
`htmlEsc`.

## What's rejected

- A missing `host`, `from`, or `to`.
- `username` without `password`, or `password` without `username`.
- `tls_mode = "off"` with a username and password: RunWisp won't send a
  password without encryption.
- A `from`, `reply_to`, `to`, `cc`, or `bcc` value that isn't a valid email
  address.
