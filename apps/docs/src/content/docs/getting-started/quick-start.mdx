RunWisp is one Go binary. You list shell commands in `runwisp.toml`, and
RunWisp runs them on a schedule or keeps them running, and records the output
of every run. It runs on Linux, macOS, and WSL, on `x86_64` or `arm64`.

## 1. Install

<Tabs syncKey="install-method">
    <TabItem label="Install script" icon="seti:shell">
        Detects your OS and CPU, downloads the matching release, checks its
        SHA-256, and puts `runwisp` on your `PATH`.

        ```bash
        curl -fsSL https://get.runwisp.com | sh
        ```
    </TabItem>
    <TabItem label="Bun / npm" icon="seti:javascript">
        The npm package pulls in the matching native binary as an optional
        dependency when it's installed.

        ```bash
        bunx runwisp              # try it without installing (or: npx runwisp)
        bun add -g runwisp        # install globally (or: npm install -g runwisp)
        ```
    </TabItem>
    <TabItem label="tar.gz" icon="download">
        Download `runwisp-{linux,darwin}-{x64,arm64}.tar.gz` from the
        [GitHub releases page][releases]. `checksums-sha256.txt` next to it
        has the checksums.

        ```bash
        tar -xzf runwisp-linux-x64.tar.gz
        sudo install -m 0755 runwisp /usr/local/bin/runwisp
        ```

        [releases]: https://github.com/runwisp/runwisp/releases
    </TabItem>
    <TabItem label="From source" icon="seti:go">
        You need Go 1.25+ and Bun.

        ```bash
        git clone https://github.com/runwisp/runwisp
        cd runwisp
        bun install
        bun run build
        ```

        The binary is at `apps/runwisp/runwisp`.
    </TabItem>
    <TabItem label="Docker" icon="seti:docker">
        ```bash
        docker run -d --name runwisp \
          -p 9477:9477 \
          -e RUNWISP_PASSWORD=change-me \
          -v ./runwisp.toml:/etc/runwisp/runwisp.toml:ro \
          -v runwisp-data:/var/lib/runwisp \
          runwisp/runwisp:latest
        ```

        See [Running in Docker](/getting-started/docker/) for image variants
        and required settings.
    </TabItem>

</Tabs>

## 2. Start RunWisp

Run `runwisp` in the directory where your config should live:

```bash
runwisp
```

If there is no `runwisp.toml` there, it asks before creating one:

```
No runwisp.toml at /home/user/myproject.
Create a starter with one example task? [Y/n]
```

Press <kbd>Enter</kbd>. RunWisp writes the file, starts the daemon in the
background, and opens the [TUI](/getting-started/tui-tour/). Answer no and
nothing is written. If the machine has cron jobs, the same prompt offers to
read them instead; see [From cron](/coming-from/cron/).

The starter file has one task and two commented examples:

```toml
# runwisp.toml
# Docs: https://docs.runwisp.com/configuration/overview/

[tasks.hello]
description = "Example task. Trigger it from the TUI (press r) or the Web UI."
run = "echo hello from runwisp"

# Schedule a task with cron:
# [tasks.heartbeat]
# cron = "* * * * *"
# run  = "date"

# Long-running service (auto-restart, supports multiple instances):
# [services.worker]
# instances = 1
# run       = "node ./worker.js"
```

On a server with no terminal (Docker, systemd), use `runwisp daemon` instead:
it never prompts, and exits with an error if the config is missing. To start
RunWisp on boot, see [Autostart](/operations/autostart/).

## 3. Run the example task

All three ways use the same daemon and show up in the same run history.

<Tabs syncKey="surface">
    <TabItem label="TUI" icon="seti:shell">
        Press <kbd>←</kbd> to focus the sidebar, move to `hello`, and press
        <kbd>r</kbd>. The run opens and its output streams in live.

        ![TUI run detail view: header with task name, run ID, timestamp, duration, and status badge; line-numbered log output below.](../../../assets/screenshots/tui-run-detail.png)

        Press <kbd>Esc</kbd> to go back to the sidebar. The
        [TUI page](/getting-started/tui-tour/) lists the other keys.
    </TabItem>
    <TabItem label="Web UI" icon="laptop">
        Open the Web UI (next step), click `hello` in the sidebar, click
        **Run**, and confirm **Run Now**. The output streams into the log pane.
    </TabItem>
    <TabItem label="CLI" icon="cloud-download">
        ```bash
        runwisp run hello
        ```

        Prints the output and exits with the task's exit code. See
        [`runwisp run`](/reference/cli/#runwisp-run).
    </TabItem>

</Tabs>

## 4. Open the Web UI

In the TUI, go to **Home** in the sidebar, select **Open Web UI**, and
press <kbd>Enter</kbd>. Your browser opens the dashboard, already logged in.

![TUI Home page: sidebar with task groups, right pane showing Open Web UI row, Web UI URL, masked password, and a recent-activity table.](../../../assets/screenshots/tui-home.png)

The Home page also shows the Web UI address (`http://localhost:9477` by
default) and the generated password. Select the password and
press <kbd>Enter</kbd> to copy it, for logging in from another browser. To set your own password or turn
login off, see [Authentication](/operations/auth/).

## 5. Make it yours

Replace `[tasks.hello]` with your own commands:

```toml
[tasks.backup-db]
cron       = "0 2 * * *"      # every day at 02:00
on_overlap = "skip"           # skip a run if the last one is still going
keep_runs  = 30
run        = "pg_dump mydb | gzip > /backups/mydb-$(date +%F).sql.gz"

[tasks.health-check]
cron = "*/5 * * * *"
run  = "curl -sf https://myapp.example.com/health"

[services.worker]
instances = 3                 # keep three copies running
run       = "node /app/worker.js"
```

A [task](/configuration/tasks/) runs on a schedule or on demand and then exits.
A [service](/configuration/services/) stays up, and RunWisp restarts it when it
exits. [Tasks vs services](/concepts/tasks-vs-services/) explains the
difference.

After editing `runwisp.toml`, run `runwisp reload`. Some settings need
`runwisp restart` instead; see [Reload](/operations/reload/).

:::tip[See it with history]
`runwisp demo` starts a throwaway instance with a sample config and hundreds
of past runs. Its data is deleted when the daemon stops (quit the TUI and
choose **Shut Down**).
:::
