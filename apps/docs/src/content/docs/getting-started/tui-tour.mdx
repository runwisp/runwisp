The TUI runs in your terminal. It connects to a daemon on the same machine over
its socket, or to a remote daemon over HTTP.

```bash
runwisp                                       # start the local daemon if needed, then open the TUI
runwisp tui                                   # open the TUI for a daemon that is already running
runwisp tui --url https://runwisp.example.com # connect to a remote daemon
```

Locally, no password is needed. With `--url`, the TUI logs in with the Web UI
password: it reads `RUNWISP_PASSWORD` or asks once, then remembers the session.
See [Authentication](/operations/auth/).

Press <kbd>?</kbd> at any time for the full list of keys. The bar at the bottom
shows the keys for whatever is focused.

## Layout

The sidebar on the left starts with three pages (Home, Info, Debug), followed
by your tasks and services, grouped by [`group`](/configuration/tasks/#group).
`▸` marks what the right pane shows. Moving the cursor does nothing until you
press <kbd>Enter</kbd>.

## Home

![TUI Home page: sidebar listing task groups, right pane showing Open Web UI row, Web UI URL, masked password, and a recent-activity table with status, duration, and trigger columns.](../../../assets/screenshots/tui-home.png)

- **Open Web UI**: opens your browser, already logged in. Without a browser, the
  TUI copies the link to your clipboard, or shows it for you to copy. Over plain
  `http://` to a remote host, it asks first, because the login link would travel
  unencrypted.
- **Web UI**: the address. <kbd>Enter</kbd> copies it.
- **Password**: shown only when the daemon generated the password.
    <kbd>Enter</kbd> copies it.
- **Recent activity**: the latest runs across all tasks.

Press <kbd>n</kbd> to open the notifications panel. If some tasks come from
crontabs that cron still runs, the header shows how many are
[held](/coming-from/cron/#held-jobs).

## Task detail

Select a task or service in the sidebar to see its schedule, a **Run Now** (or
**Restart**) button, and its run history. **Run Now** asks for confirmation, or
opens a form if the task has [parameters](/concepts/parameters/).

![TUI task detail for healthcheck-api: header with task name, cron schedule, next-fire countdown, and Run Now button; run history table below showing status, start time, duration, and trigger columns.](../../../assets/screenshots/tui-task-detail.png)

- <kbd>f</kbd> filters the runs by status. A banner shows while a filter is active.
- <kbd>i</kbd> shows the task's full definition and recent health.
- <kbd>space</kbd> selects runs, <kbd>a</kbd> selects all that match the filter. Then <kbd>d</kbd>
  deletes, <kbd>c</kbd> cancels, and <kbd>e</kbd>
  re-runs them. <kbd>u</kbd> undoes a delete while its notice is showing.

## Following a run

Press <kbd>Enter</kbd> on a run to open it. The log streams live, with line
numbers, under a header with the run ID, start time, duration, status, and exit
code.

![TUI run detail for reindex-search: header with Back button, run ID, timestamp, duration, SUCCESS badge, and exit code; line-numbered log output below.](../../../assets/screenshots/tui-run-detail.png)

- The log follows new lines. Scrolling up pauses that; <kbd>G</kbd> jumps back
  to the end and follows again.
- <kbd>f</kbd> shows only the log, full screen, for copying.
- <kbd>d</kbd> downloads the log. Without a browser, you get the download link instead.
- <kbd>r</kbd> runs it again, <kbd>s</kbd> stops it. Both ask first.
- <kbd>i</kbd> shows the run's exit code, trigger, timing, and retries. For a retry,
  <kbd>Enter</kbd> jumps to the attempt it retried.

![TUI fullscreen log view: no sidebar, no header, pure log lines filling the terminal.](../../../assets/screenshots/tui-fullscreen-mode.png)

## Reading a failure

The run header tells you what went wrong before you read the log:

- **Status**: why the run ended: `failed`, `timeout`, `crashed`, `stopped`,
  `skipped`, `log_overflow`, and others.
- **Exit code**: what the command returned. `-1` means the run was skipped and
  never started ([`on_overlap = "skip"`](/configuration/tasks/#on_overlap)).
  `-2` means the daemon died during the run (`crashed`). A timeout usually shows
  `143` (SIGTERM) or `137` (SIGKILL).

In the sidebar, a task whose last run failed has a coloured marker. With
[retries](/concepts/retries/), every attempt is its own run with its own log.

## Info and Debug

**Info** shows CPU and memory graphs, run counts, version, and uptime.

![TUI Info page: CPU and memory sparklines, activity summary, version and platform details, configuration checkmarks, and task list.](../../../assets/screenshots/tui-info.png)

**Debug** shows the daemon's own log. Reconnect messages appear here when the
connection drops. The TUI reconnects by itself.

## Keyboard shortcuts

| Key                                                 | Action                                                |
| --------------------------------------------------- | ----------------------------------------------------- |
| <kbd>?</kbd>                                        | Show all keys                                         |
| <kbd>q</kbd> / <kbd>Ctrl+C</kbd>                    | Quit                                                  |
| <kbd>↑</kbd><kbd>↓</kbd> / <kbd>k</kbd><kbd>j</kbd> | Move                                                  |
| <kbd>←</kbd><kbd>→</kbd> / <kbd>h</kbd><kbd>l</kbd> | Switch between sidebar and main pane                  |
| <kbd>Enter</kbd>                                    | Open, activate, or copy a field                       |
| <kbd>Esc</kbd> / <kbd>⌫</kbd>                       | Back                                                  |
| <kbd>/</kbd>                                        | Filter tasks (sidebar) or search the task's logs      |
| <kbd>r</kbd>                                        | Run now (task), restart (service), or retry (run)     |
| <kbd>s</kbd>                                        | Stop a run or service                                 |
| <kbd>R</kbd>                                        | Reload `runwisp.toml` ([Reload](/operations/reload/)) |
| <kbd>n</kbd>                                        | Notifications panel (on Home)                         |
| <kbd>i</kbd>                                        | Task or run details                                   |
| <kbd>f</kbd>                                        | Filter runs, or full-screen log in a run              |
| <kbd>d</kbd> / <kbd>D</kbd>                         | In a run: download the log / delete the run           |
| <kbd>g</kbd> / <kbd>G</kbd>                         | Jump to the top / end of the log                      |

## Quitting

Press <kbd>q</kbd>. The TUI asks whether to keep the daemon running in the
background or shut it down. <kbd>Esc</kbd> cancels.

![TUI quit confirmation dialog: modal asking "Keep the daemon running in the background?" with Keep Running and Shut Down buttons.](../../../assets/screenshots/tui-quit-confirmation.png)

- **Shut Down** stops the local daemon, also under `runwisp tui`. Connected
  with `--url`, it only closes the TUI.
- A daemon run by systemd or launchd has no **Shut Down** option. Use
  `runwisp stop`.
